材料高通量数据自动化处理平台架构说明书
本平台是一个基于 Python 开发的材料高通量数据自动化清洗、整合与 Origin 自动化控制绘图的科研软件。系统采用“大管家外壳 + 独立文件夹插件”的模块化结构设计。

一、 控制中心：启动器外壳 (Launcher.py)
启动器负责提供软件的主界面、管理多标签页、控制整体视觉皮肤，并为后续所有的插件脚本提供底层的运行环境支持。

1. 关键设计逻辑：
模块化文件夹扫描：软件启动时，会自动扫描身边的 Features 文件夹。只要发现里面有子文件夹（如 Features/磁光克尔/），并且里面躺着一个同名的 .py 脚本（如 磁光克尔.py），就会自动把它加载成软件顶部的一个新标签页。

无感环境注入（一劳永逸）：在外壳的最顶部，明面导入了 pandas、originpro 以及 tkinter 的所有常用高级弹窗和文本框组件。这样打包成 .exe 时，所有的科研工具箱都会被强行装进盒子里，后续添加任何新脚本，只要用到这些库，直接写就行，这辈子都不需要重新打包 .exe。

自由缩放与中心锚定：解锁了窗口最大化和拉伸的权限。利用双层嵌套网格计算，当用户双击放大软件时，所有的控制面板和按钮作为一个整体永远稳居在屏幕正中央，绝不会野蛮拉伸变形。

递归日夜间换色引擎：右上角有一键切换主题按钮。采用深入递归算法，切换时会自动向下渗透到所有加载的插件脚本中，强行把所有传统的文本框、按钮以及现代组件（TFrame等）同步染成对应的日间或夜间色系，并且彻底消除了 Windows 原生组件在夜间模式下左上角产生白边和白块的缺陷。

二、 功能插件：磁光克尔模块 (磁光克尔.py)
这是平台挂载的第一款高通量核心插件，实现了从“多包、多角度数据提取”到“套用克隆模板自动画热力图”的一条龙流水线。

1. 核心关键方法：
build_sub_interface(parent) 入口函数：这是外壳与插件对接的唯一标准接口。启动器加载脚本时，会把当前标签页的画布传进来，脚本里的所有输入框和按钮都会整齐地绘制在它里面。

TextRedirector 实时日志重定向：利用这个自定义类，把 Python 代码里所有的 print() 文字，全部实时接管并输送到软件界面下方的运行日志大框里，让用户清晰看到后台的执行进度。

智能模板自动寻桩：脚本启动时，会自动抓取它自己所在的子文件夹路径。自动扫描里面带有 hc 或 m2 关键字的 .otpu 模板文件，并自作聪明地直接把路径预填到输入框中，省去了用户每次手动寻找模板的麻烦。

内存不落地一条龙（功能3）：启动后直接在内存里新建工作簿，解压清洗完所有压缩包数据后，绝不急着存盘落地，而是直接在内存里无缝调用克隆模板把所有热力图画完，最后执行唯一一次总存盘。速度快且极为稳妥。

2. 终极避雷核心：Windows 原生反斜杠约束（重要！）
问题表现：在第二步“仅自动绘图”或连续点击对已经存在的 .opju 文件进行覆盖保存时，Origin 内部的备份机制会被强行唤醒。如果路径里带有正斜杠 /，Origin 死板的 C++ 拼接引擎就会拼出畸形的 Backup\/Desktop/ 错误路径，导致系统无法创建文件夹，从而中止保存，提示“保存已中止，文件未保存！”

解决方法：在 clean_path() 函数中，利用 .replace('/', '\\') 逻辑，把所有通过界面或弹窗拿到的路径，全部强行换成 Windows 系统最纯正的反斜杠 \。这样 Origin 内部的备份引擎就能正常拼出合法的 Windows 路径，直接顺利通过，彻底根治了覆盖已有文件时闪退报错的底层顽疾。

三、 未来如何新增一个功能板块？
如果以后你想添加新的实验数据处理板块（例如：高通量硬度数据处理），你只需要按部就班地做以下两步，完全不需要动 Launcher.py 和 .exe 文件：

在 Features 文件夹下新建一个对应的功能文件夹，比如 Features/高通量硬度/。

在里面放一个写好了核心功能的 高通量硬度.py。

只要在这个 .py 脚本里，保留标准的 def build_sub_interface(parent): 入口函数，并确保所有送给 Origin 的文件路径全部使用 \ 反斜杠，软件启动时就会自动把它接纳为一个全新的控制标签页，即插即用！
